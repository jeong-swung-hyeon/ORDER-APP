# 커피 주문 앱

## 1. 프로젝트 개요

### 1.1 프로젝트명
커피 주문 앱

### 1.2 프로젝트 목적
사용자가 커피 메뉴를 주문하고, 관리자가 주문을 관리할 수 있는 간단한 풀스택 웹 앱

### 1.3 개발 범위
- 주문하기 화면(메뉴 선택 및 장바구니 기능)
- 관리자 화면(재고 관리 및 주문 상태 관리)
- 데이터를 생성/조회/수정/삭제할 수 있는 기능

## 2. 기술 스택
- 프런트엔드 : HTML, CSS, 리액트, 자바스크립트
- 백엔드 : Node.js, Express
- 데이터베이스 : PostgreSQL

## 3. 기본사항
- 프런트엔드와 백엔드를 따로 개발
- 기본적인 웹 기술만 사용
- 학습 목적이므로 사용자 인증이나 결제 기능은 제외
- 메뉴는 커피 메뉴만 있음

## 4. 주문하기 화면 상세 요구사항

### 4.1 화면 구성

#### 4.1.1 헤더 영역
- **위치**: 화면 상단
- **구성 요소**:
  - **로고**: 왼쪽에 "COZY" 텍스트가 들어간 흰색 배경의 박스 (검은색 테두리)
  - **주문하기 버튼**: 로고 오른쪽에 위치, 현재 화면을 나타내는 버튼 (흰색 배경, 검은색 테두리)
  - **관리자 버튼**: 주문하기 버튼 오른쪽에 위치, 관리자 화면으로 이동하는 버튼 (흰색 배경, 검은색 테두리)

#### 4.1.2 메뉴 아이템 영역
- **위치**: 헤더 아래, 화면 중앙
- **레이아웃**: 메뉴 아이템들이 가로로 나열된 카드 형태
- **각 메뉴 카드 구성 요소**:
  1. **메뉴 이미지**: 카드 상단에 위치한 이미지 영역
  2. **메뉴 이름**: 이미지 아래에 표시되는 메뉴명 (예: "아메리카노(ICE)", "아메리카노(HOT)", "카페라떼")
  3. **가격**: 메뉴 이름 아래에 표시되는 기본 가격 (예: "4,000원", "5,000원")
  4. **설명**: 가격 아래에 표시되는 간단한 설명 텍스트 (예: "간단한 설명...")
  5. **커스터마이징 옵션**: 체크박스 형태의 옵션들
     - "샷 추가 (+500원)" 옵션
     - "시럽 추가 (+0원)" 옵션 (무료 옵션이나 0원으로 표기)
  6. **담기 버튼**: 카드 하단에 위치한 흰색 배경의 라운드 버튼 (검은색 테두리), 클릭 시 장바구니에 추가

#### 4.1.3 장바구니 영역
- **위치**: 화면 하단
- **구성 요소**:
  1. **장바구니 제목**: "장바구니" 텍스트
  2. **장바구니 아이템 목록**: 추가된 메뉴들이 리스트 형태로 표시
     - 각 아이템은 메뉴명, 옵션 정보, 수량, 가격을 포함
     - 예: "아메리카노(ICE) (샷 추가) X 1" - "4,500원"
     - 예: "아메리카노(HOT) X 2" - "8,000원"
     - 각 아이템마다 수량 조절 버튼(+/-) 또는 삭제 버튼(X) 제공
  3. **총 금액**: 아이템 목록 오른쪽에 "총 금액" 라벨과 함께 굵은 글씨로 표시
     - 예: "총 금액 12,500원"
  4. **주문하기 버튼**: 총 금액 아래에 위치한 버튼
     - 장바구니에 아이템이 있을 때: 활성화 상태 (흰색 배경, 검은색 테두리)
     - 장바구니가 비어있을 때: 비활성화 상태 (회색 배경, 흐리게 처리)

### 4.2 기능 요구사항

#### 4.2.1 메뉴 표시 기능
- 서버에서 메뉴 데이터를 가져와 화면에 표시
- 각 메뉴는 이미지, 이름, 가격, 설명 정보를 포함
- 메뉴는 카드 형태로 세로 그리드 레이아웃으로 표시 (모바일과 웹 공통으로 직관적인 레이아웃)

#### 4.2.2 커스터마이징 옵션 기능
- 각 메뉴 카드에서 옵션을 선택할 수 있음
- 옵션 선택 시 추가 가격이 반영됨
  - 옵션을 선택하면 메뉴 카드 내의 가격이 실시간으로 업데이트됨 (예: 4,000원 → 4,500원)
  - 옵션 해제 시 가격도 즉시 원래 가격으로 복원됨
- 옵션은 다중 선택 가능 (예: 샷 추가 + 시럽 추가)
- 옵션 가격이 0원인 경우에도 명시적으로 표기 (예: "시럽 추가 (+0원)")

#### 4.2.3 장바구니 기능
- **담기 버튼 클릭 시**:
  - 선택한 메뉴와 옵션 정보를 장바구니에 추가
  - 동일한 메뉴와 옵션 조합이 이미 있으면 수량 증가
  - 장바구니에 추가된 아이템은 하단 장바구니 영역에 표시
- **장바구니 아이템 표시**:
  - 메뉴명, 선택한 옵션, 수량, 개별 가격 표시
  - 총 금액 자동 계산 및 표시
- **수량 관리**: 
  - 동일한 메뉴+옵션 조합은 수량으로 관리
  - 각 아이템마다 수량 증가/감소 버튼(+/-) 제공
  - 수량이 1일 때 감소 버튼 클릭 시 해당 아이템 삭제
  - 각 아이템마다 삭제 버튼(X) 제공하여 즉시 삭제 가능
  - 수량 변경 또는 삭제 시 총 금액이 실시간으로 업데이트됨

#### 4.2.4 주문하기 기능
- 장바구니에 아이템이 있을 때만 주문하기 버튼 활성화
  - 활성화 상태: 정상적인 클릭 가능한 상태
  - 비활성화 상태: 회색 배경으로 흐리게 처리되어 클릭 불가
- 주문하기 버튼 클릭 시:
  - 장바구니의 모든 아이템과 총 금액을 서버로 전송
  - 주문 완료 후 장바구니 초기화
  - 주문 성공/실패에 대한 피드백 제공

#### 4.2.5 네비게이션 기능
- 관리자 버튼 클릭 시 관리자 화면으로 이동
- 주문하기 버튼은 현재 화면을 나타내는 표시 역할

### 4.3 UI/UX 요구사항

#### 4.3.1 디자인
- 깔끔하고 미니멀한 디자인
- 배경: 흰색
- 텍스트: 다크 그레이
- 버튼 및 로고: 흰색 배경에 검은색 테두리 (라인 스타일)
- 비활성화 버튼: 회색 배경으로 흐리게 처리

#### 4.3.2 반응형 디자인
- 다양한 화면 크기에 대응 가능한 레이아웃
- 모바일 환경에서도 사용 가능하도록 고려

#### 4.3.3 사용자 경험
- 직관적인 인터페이스
- 버튼 클릭 시 명확한 피드백 제공
- 장바구니에 추가된 아이템이 즉시 하단에 표시됨
- 총 금액이 실시간으로 업데이트됨

### 4.4 데이터 구조

#### 4.4.1 메뉴 데이터
```javascript
{
  id: number,
  name: string,
  price: number,
  description: string,
  image: string,
  options: [
    {
      name: string,
      price: number
    }
  ]
}
```

#### 4.4.2 장바구니 아이템 데이터
```javascript
{
  cartItemId: string, // 고유 식별자 (UUID 또는 타임스탬프 기반)
  menuId: number,
  menuName: string,
  basePrice: number,
  selectedOptions: [
    {
      name: string,
      price: number
    }
  ],
  quantity: number,
  totalPrice: number
}
```
**참고**: `cartItemId`는 같은 `menuId`와 `selectedOptions` 조합이라도 장바구니에서 별개의 아이템으로 구분하기 위한 고유 키입니다. 예를 들어, '아메리카노 샷 추가'와 '아메리카노 샷 미추가'는 같은 `menuId`를 가지지만 다른 `cartItemId`를 가집니다.

#### 4.4.3 주문 데이터
```javascript
{
  id: number,
  items: [
    {
      menuId: number,
      menuName: string,
      options: string[],
      quantity: number,
      price: number
    }
  ],
  totalAmount: number,
  status: string, // 'pending', 'received', 'preparing', 'completed', 'cancelled'
  orderDate: timestamp
}
```

## 5. 관리자 화면 상세 요구사항

### 5.1 화면 구성

#### 5.1.1 헤더 영역
- **위치**: 화면 상단
- **구성 요소**:
  - **로고**: 왼쪽에 "COZY" 텍스트가 들어간 흰색 배경의 박스 (검은색 테두리)
  - **주문하기 버튼**: 로고 오른쪽에 위치, 주문하기 화면으로 이동하는 버튼 (흰색 배경, 검은색 테두리)
  - **관리자 버튼**: 주문하기 버튼 오른쪽에 위치, 현재 화면을 나타내는 버튼 (흰색 배경, 검은색 테두리)

#### 5.1.2 관리자 대시보드 요약 영역
- **위치**: 헤더 아래, 화면 상단
- **디자인**: 연한 회색 배경의 둥근 모서리 박스
- **구성 요소**: 주문 통계 정보를 한눈에 볼 수 있는 요약 카드
  - **총 주문**: 전체 주문 건수 표시 (예: "총 주문 1")
  - **주문 접수**: 주문 접수 상태인 주문 건수 표시 (예: "주문 접수 1")
  - **제조 중**: 제조 중 상태인 주문 건수 표시 (예: "제조 중 0")
  - **제조 완료**: 제조 완료 상태인 주문 건수 표시 (예: "제조 완료 0")
- **레이아웃**: 통계 항목들이 가로로 나열되어 표시

#### 5.1.3 재고 현황 영역
- **위치**: 관리자 대시보드 요약 영역 아래
- **디자인**: 연한 회색 배경의 둥근 모서리 박스
- **구성 요소**:
  1. **제목**: "재고 현황" 텍스트
  2. **메뉴별 재고 카드**: 각 메뉴 아이템별로 재고 정보를 카드 형태로 표시
     - **메뉴 이름**: 카드 상단에 메뉴명 표시 (예: "아메리카노 (ICE)", "아메리카노 (HOT)", "카페라떼")
     - **재고 수량**: 메뉴 이름 아래에 현재 재고 수량 표시 (예: "10개")
     - **재고 조절 UI**: 재고 수량 아래에 배치
       - **+ 버튼 / - 버튼**: 1단위 증감
       - **+10 / -10 버튼**: 10단위 증감
       - **직접 입력 필드**: 숫자 입력 후 확인 시 해당 수량으로 설정
- **레이아웃**: 메뉴 카드들이 가로로 나열되어 표시

#### 5.1.4 주문 현황 영역
- **위치**: 재고 현황 영역 아래, 화면 하단
- **디자인**: 연한 회색 배경의 둥근 모서리 박스
- **구성 요소**:
  1. **제목**: "주문 현황" 텍스트
  2. **주문 목록**: 주문들이 리스트 형태로 표시
     - 각 주문 항목은 다음 정보를 포함:
       - **주문 시간**: 주문이 들어온 날짜와 시간 (예: "7월 31일 13:00")과 상대 시간(예: "방금 전", "5분 전") 병기
       - **주문 내역**: 주문한 메뉴, 수량, 옵션을 모두 표시 (예: "아메리카노(ICE) x 1 / 옵션: 샷 추가")
       - **주문 금액**: 해당 주문의 총 금액 (예: "4,000원")
       - **주문 상태 변경/취소 버튼**: 다음 동작을 나타내는 버튼(텍스트는 수행할 동작 기준)
         - 예: 현재 상태가 대기 중일 때 버튼 텍스트 "주문 접수"
         - 상태에 따라 "제조 시작", "제조 완료"로 변경
         - 취소가 필요한 경우 별도 "주문 취소" 버튼 제공 (흰색 배경, 검은색 테두리)

### 5.2 기능 요구사항

#### 5.2.1 관리자 대시보드 요약 기능
- **통계 데이터 조회**:
  - 서버에서 주문 통계 데이터를 가져와 화면에 표시
  - 총 주문, 주문 접수, 제조 중, 제조 완료 건수를 실시간으로 계산하여 표시
- **실시간 업데이트**:
  - 주문 상태가 변경되면 통계 데이터가 자동으로 업데이트됨
  - 페이지 새로고침 없이 최신 통계 정보 유지 (WebSocket 또는 SSE 기반 실시간 반영)

#### 5.2.2 재고 관리 기능
- **재고 조회**:
  - 서버에서 각 메뉴별 재고 데이터를 가져와 화면에 표시
  - 메뉴별로 현재 재고 수량을 카드 형태로 표시
- **재고 증가**:
  - + 버튼 클릭 시 해당 메뉴의 재고가 1 증가
  - +10 버튼 클릭 시 10 증가
  - 재고 증가 시 서버로 업데이트 요청 전송
  - 재고 수량이 즉시 화면에 반영됨
- **재고 감소**:
  - - 버튼 클릭 시 해당 메뉴의 재고가 1 감소
  - -10 버튼 클릭 시 10 감소
  - 재고가 0보다 작아지지 않도록 유효성 검사 (0 이하로 감소 불가)
  - 재고 감소 시 서버로 업데이트 요청 전송
  - 재고 수량이 즉시 화면에 반영됨
- **직접 입력**:
  - 재고 수량 입력 필드에 숫자를 직접 입력 후 확인 시 해당 수량으로 설정
  - 음수 입력은 불가하도록 검증
- **품절 연동**:
  - 재고가 0이 되면 주문하기 화면에서 해당 메뉴를 자동으로 "품절(Sold Out)" 처리하여 담기 불가
  - 재고가 1 이상으로 복구되면 품절 상태를 해제

#### 5.2.3 주문 현황 관리 기능
- **주문 목록 조회**:
  - 서버에서 주문 데이터를 가져와 화면에 표시
  - 최신 주문이 상단에 표시되도록 정렬 (시간 역순)
  - 각 주문은 주문 시간, 주문 내역, 주문 금액, 현재 상태를 포함
- **주문 상태 변경**:
  - 주문 상태 변경 버튼 클릭 시 해당 주문의 상태가 다음 단계로 변경됨
  - 주문 상태 흐름: 주문 접수 → 제조 중 → 제조 완료
  - 상태 변경 시 서버로 업데이트 요청 전송
  - 상태 변경 후 주문 목록과 대시보드 통계가 자동으로 업데이트됨
  - 버튼 텍스트는 **현재 상태가 아닌, 수행할 동작**을 나타냄
    - 대기 중(pending): "주문 접수"
    - 주문 접수(received): "제조 시작"
    - 제조 중(preparing): "제조 완료"
    - 제조 완료(completed): 버튼 비활성화 또는 "완료" 표시
- **주문 취소**:
  - 각 주문 항목에 "주문 취소" 버튼 제공
  - 취소 시 상태를 cancelled로 설정하고 서버로 업데이트 요청 전송
  - 취소 후 목록과 대시보드 통계가 자동으로 업데이트됨
- **주문 상세 정보 표시**:
  - 주문 내역에 옵션 정보를 포함하여 표시 (예: "아메리카노(ICE) x 1 / 옵션: 샷 추가")

#### 5.2.4 네비게이션 기능
- 주문하기 버튼 클릭 시 주문하기 화면으로 이동
- 관리자 버튼은 현재 화면을 나타내는 표시 역할

## 6. 백엔드 개발 요구사항

### 6.1 데이터 모델 설계

#### 6.1.1 Menus 테이블
커피 메뉴 정보를 저장하는 테이블

**필드 구조:**
- `id` (number, Primary Key): 메뉴 고유 식별자
- `name` (string): 커피 이름 (예: "아메리카노(ICE)", "카페라떼")
- `description` (string): 메뉴 설명 (예: "시원하고 깔끔한 아이스 아메리카노")
- `price` (number): 기본 가격 (예: 4000)
- `image` (string): 이미지 파일 경로 또는 URL (예: "/1.png")
- `stock` (number): 재고 수량 (기본값: 10)
- `created_at` (timestamp): 생성 일시
- `updated_at` (timestamp): 수정 일시

**예시 데이터:**
```sql
INSERT INTO menus (id, name, description, price, image, stock) VALUES
(1, '아메리카노(ICE)', '시원하고 깔끔한 아이스 아메리카노', 4000, '/1.png', 10),
(2, '아메리카노(HOT)', '따뜻하고 진한 핫 아메리카노', 4000, '/2.png', 10),
(3, '카페라떼', '부드러운 우유와 에스프레소의 조화', 5000, '/3.png', 10),
(4, '카푸치노', '에스프레소와 스팀 우유, 우유 거품의 완벽한 조합', 5000, '/4.png', 10),
(5, '카라멜 마키아토', '달콤한 카라멜 시럽이 들어간 특별한 커피', 5500, '/5.png', 10),
(6, '바닐라 라떼', '부드러운 바닐라 향이 가득한 라떼', 5500, '/6.png', 10);
```

#### 6.1.2 Options 테이블
메뉴 옵션 정보를 저장하는 테이블

**필드 구조:**
- `id` (number, Primary Key): 옵션 고유 식별자
- `menu_id` (number, Foreign Key): 연결된 메뉴 ID (Menus 테이블 참조)
- `name` (string): 옵션 이름 (예: "샷 추가", "시럽 추가")
- `price` (number): 옵션 추가 가격 (예: 500, 0)
- `created_at` (timestamp): 생성 일시
- `updated_at` (timestamp): 수정 일시

**예시 데이터:**
```sql
INSERT INTO options (id, menu_id, name, price) VALUES
(1, 1, '샷 추가', 500),
(2, 1, '시럽 추가', 0),
(3, 2, '샷 추가', 500),
(4, 2, '시럽 추가', 0);
-- 모든 메뉴에 동일한 옵션 적용 가능
```

#### 6.1.3 Orders 테이블
주문 정보를 저장하는 테이블

**필드 구조:**
- `id` (number, Primary Key): 주문 고유 식별자
- `order_date` (timestamp): 주문 일시
- `total_amount` (number): 주문 총 금액
- `status` (string): 주문 상태 ('pending', 'received', 'preparing', 'completed', 'cancelled')
- `created_at` (timestamp): 생성 일시
- `updated_at` (timestamp): 수정 일시

**예시 데이터:**
```sql
INSERT INTO orders (id, order_date, total_amount, status) VALUES
(1, '2024-07-31 13:00:00', 12500, 'received');
```

#### 6.1.4 Order_Items 테이블
주문 상세 내역을 저장하는 테이블 (Orders와 1:N 관계)

**필드 구조:**
- `id` (number, Primary Key): 주문 아이템 고유 식별자
- `order_id` (number, Foreign Key): 주문 ID (Orders 테이블 참조)
- `menu_id` (number, Foreign Key): 메뉴 ID (Menus 테이블 참조)
- `menu_name` (string): 메뉴 이름 (주문 시점의 메뉴명 저장)
- `quantity` (number): 주문 수량
- `unit_price` (number): 단가 (메뉴 가격 + 옵션 가격)
- `options` (string[] 또는 JSON): 선택한 옵션 목록 (예: ["샷 추가", "시럽 추가"])
- `created_at` (timestamp): 생성 일시

**예시 데이터:**
```sql
INSERT INTO order_items (id, order_id, menu_id, menu_name, quantity, unit_price, options) VALUES
(1, 1, 1, '아메리카노(ICE)', 1, 4500, '["샷 추가"]'),
(2, 1, 2, '아메리카노(HOT)', 2, 4000, '[]');
```

**데이터 전송**: 없음 (클라이언트 측에서만 처리)
**서버 처리**: 없음 (장바구니는 클라이언트 측 상태 관리)

#### 6.2.3 주문하기 흐름
**사용자 행동**: 장바구니에서 "주문하기" 버튼 클릭
**데이터 전송**: 
```javascript
POST /api/orders
{
  items: [
    {
      menuId: 1,
      menuName: '아메리카노(ICE)',
      options: ['샷 추가'],
      quantity: 1,
      price: 4500
    },
    {
      menuId: 2,
      menuName: '아메리카노(HOT)',
      options: [],
      quantity: 2,
      price: 4000
    }
  ],
  totalAmount: 12500
}
```

**서버 처리**:
1. 주문 데이터 유효성 검증
   - 메뉴 ID 존재 여부 확인
   - 재고 수량 확인 (주문 수량 ≤ 가용 재고)
   - 가격 계산 검증
2. 트랜잭션 시작
3. Orders 테이블에 주문 정보 저장
   - `order_date`: 현재 시간
   - `total_amount`: 총 금액
   - `status`: 'received' (주문 접수 상태)
4. Order_Items 테이블에 주문 상세 내역 저장
   - 각 아이템별로 레코드 생성
5. Menus 테이블의 재고 수량 업데이트
   - 주문된 각 메뉴의 재고에서 주문 수량만큼 차감
   - 재고가 0 이하로 내려가지 않도록 검증
6. 트랜잭션 커밋
7. 생성된 주문 ID와 함께 성공 응답 반환

**응답 데이터:**
```javascript
{
  success: true,
  orderId: 123,
  message: '주문이 완료되었습니다.'
}
```

**에러 처리:**
- 재고 부족 시: `400 Bad Request` - "재고가 부족합니다."
- 잘못된 메뉴 ID: `400 Bad Request` - "존재하지 않는 메뉴입니다."
- 서버 오류: `500 Internal Server Error` - "주문 처리 중 오류가 발생했습니다."

#### 6.2.5 주문 상태 변경 흐름
**사용자 행동**: 관리자 화면에서 "제조 시작" 또는 "제조 완료" 버튼 클릭

1. 주문 ID로 Orders 테이블에서 주문 조회
2. 주문 존재 여부 확인
3. 상태 변경 유효성 검증
   - 'received' → 'preparing' → 'completed' 순서 확인
   - 이미 완료된 주문은 상태 변경 불가
4. Orders 테이블의 status 필드 업데이트
5. 성공 응답 반환

#### 6.2.6 주문 취소 흐름
**사용자 행동**: 관리자 화면에서 "주문 취소" 버튼 클릭
**데이터 전송**:
```javascript
PATCH /api/orders/:orderId/status
```

**서버 처리**:
1. 주문 ID로 Orders 테이블에서 주문 조회
2. 주문 존재 여부 확인
3. 이미 완료된 주문은 취소 불가 (검증)
4. Orders 테이블의 status를 'cancelled'로 업데이트
5. 주문 취소 시 재고 복구
   - Order_Items를 조회하여 주문된 메뉴와 수량 확인
   - Menus 테이블에서 해당 메뉴의 재고를 주문 수량만큼 증가
6. 성공 응답 반환

### 6.4 데이터베이스 관계도

```
Menus (1) ────< (N) Options
  │
  │ (1)
  │
  │ (N)
Order_Items ────< (N) Orders
```

**관계 설명:**
- Menus : Options = 1 : N (한 메뉴에 여러 옵션)
- Orders : Order_Items = 1 : N (한 주문에 여러 주문 아이템)
- Order_Items : Menus = N : 1 (주문 아이템은 하나의 메뉴 참조)

### 6.5 주요 비즈니스 로직

#### 6.5.1 재고 관리 로직
- 주문 생성 시: 주문 수량만큼 재고 차감
- 주문 취소 시: 주문 수량만큼 재고 복구
- 재고는 0 이하로 내려가지 않도록 검증
- 관리자가 직접 재고 수정 가능

#### 6.5.2 주문 상태 관리 로직
- 주문 생성 시 기본 상태: 'received' (주문 접수)
- 상태 변경 흐름: 'received' → 'preparing' → 'completed'
- 'completed' 또는 'cancelled' 상태는 더 이상 변경 불가
- 주문 취소는 'received' 또는 'preparing' 상태에서만 가능

#### 6.5.3 가격 계산 로직
- 주문 아이템 가격 = (메뉴 기본 가격 + 선택한 옵션 가격 합계) × 수량
- 주문 총 금액 = 모든 주문 아이템 가격의 합계
- 클라이언트와 서버 양쪽에서 가격 검증 수행
